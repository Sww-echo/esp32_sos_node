# 实施计划：独居老人 SOS 按钮多通道通知

## 阶段 0：基线确认

- [ ] 记录当前板卡识别信息、Flash/PSRAM、串口日志和当前 MQTT 行为。
- [ ] 确认 BOOT 键可作为开发阶段触发输入，并明确 GPIO0 不能进入生产版。
- [ ] 确认 MQTT broker、测试账号、订阅工具和 Node-RED/Home Assistant 的运行位置。

## 阶段 1：设备端最小闭环

- [ ] 在 `app_config.h` 增加按钮、LED、蜂鸣器、心跳和报警重试配置。
- [ ] 在 `main.cpp` 增加按钮防抖、长按策略和本地提示。
- [ ] 生成稳定的 `device_id` 和单调递增事件序号，组成 `event_id`。
- [ ] 发布 `devices/<device-id>/alert`，记录日志和最近报警状态。
- [ ] 将 BOOT 键报警与网页测试报警接到同一事件函数。

## 阶段 2：可靠投递

- [ ] 用 `Preferences` 或单独 NVS 命名空间保存未确认事件和序号。
- [ ] 增加 ACK 主题订阅、事件 ID 校验和状态转换。
- [ ] 增加 MQTT 断线重连、指数退避、最大重试和重启恢复。
- [ ] 明确 QoS 1、保留消息、非保留报警和服务端幂等规则。
- [ ] 增加 heartbeat、LWT 和离线检测字段。

## 阶段 3：网页和可观测性

- [ ] 在管理网页显示报警状态、事件 ID、ACK 时间、队列长度和失败原因。
- [ ] 增加受保护的“测试报警”按钮和二次确认。
- [ ] 把报警状态转换、重试、ACK 和队列恢复接入现有日志 API。
- [ ] 更新 README，写清主题、载荷、引脚、生产安全要求和调试步骤。

## 阶段 4：通知编排

- [ ] 用 Node-RED 或 Home Assistant 订阅 alert/heartbeat/status。
- [ ] 先接入 ntfy 或 Telegram，完成手机端端到端通知。
- [ ] 增加事件去重、ACK 回传、静默窗口和通知升级策略。
- [ ] 再接入 Twilio 等 SMS/电话渠道，并将第三方凭证放在服务端环境变量中。

## 阶段 5：硬件和生产化

- [ ] 接入独立 GPIO 的实体大按钮、LED 和蜂鸣器，完成按键电气测试。
- [ ] 增加看门狗、异常断电和重启恢复测试。
- [ ] 评估 OTA、TLS 证书管理、设备独立账号和 ACL。
- [ ] 后续再做电池、深睡眠和 4G 备份，不与第一版联网闭环混在一起。

## 验证矩阵

| 场景 | 预期结果 |
| --- | --- |
| MQTT 在线按键 | 本地提示，发布 alert，收到 ACK 后结束 |
| MQTT 断开按键 | 事件进入 Flash 队列，恢复连接后重发 |
| 设备重启 | 未 ACK 事件恢复，event_id 不变 |
| 重复 ACK | 不产生异常，也不重复触发通知 |
| 重复按键 | 在防抖/冷却策略内不产生风暴 |
| broker 发布重复 | 服务端按 event_id 幂等，不重复通知 |
| 心跳超时 | 服务端发送设备离线告警 |
| 网页测试报警 | 经过确认并走与实体按钮相同的事件管线 |
| 生产按钮接线 | 不影响启动，不使用 GPIO0 |
